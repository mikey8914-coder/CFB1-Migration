## Preservation rules

The Colab notebook is the reference implementation. Preserve the existing quantitative logic, constants, sign conventions, row selection, rounding, ordering, warnings, and exported schemas before cleanup. Python remains the source of truth for deterministic CFB1 outputs. Do not add handicapping logic or reinterpret ambiguous routes.

Normal CFB1 market inputs are spread and game total only. Future acquisition should use Action Network first and Covers as gap-fill; missing games may be excluded rather than aggressively searched. The notebook currently uses The Odds API and has no Action Network implementation. Exact sportsbook prices, props, promos, and Odds API usage belong primarily to Bet Slip Architect. Changing acquisition or moving pricing ownership must be a separate, explicitly validated transition, not an incidental extraction cleanup.

## Validation strategy for future work

Start with deterministic offline replay against known historical Colab outputs before live service checks. At each boundary compare input population and provenance, schemas, normalized names, join cardinality, missing values, row order, intermediate numeric values, signal flags, route strings, decision classes, and final exports. Record any permitted floating-point tolerance explicitly; do not hide material differences by rounding or broad tolerances.

Include already-supported edge cases: opposite home/away orientations, pick'em, keys at endpoints, large-spread thresholds, simultaneous support/conflict, whole/half-point lines, sparse historical buckets, absent pricing, and qualitative-only routes. Preserve existing errors and guard behavior until an intentional change is separately authorized. Manual header-only pricing is an awaiting-input state, not proof that downstream pricing works.

Historical acquisition includes 2021–2025 while weekly settings currently select 2026, completed week 5, target week 6, and October 6–10. Freeze exact baseline settings and data timestamps rather than replacing them with current-date defaults. Known historical Colab outputs and acquisition payloads still need to be established as a coherent baseline; static notebook inspection does not verify numerical parity or runtime readiness.

Keep the acquisition layer separate from model logic. If changing sources changes slate coverage, measure the resulting fit/percentile changes explicitly. Do not claim extraction parity and source-policy parity are the same check.
