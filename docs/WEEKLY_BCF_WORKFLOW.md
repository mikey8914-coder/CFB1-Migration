# Production weekly BCF input workflow

## Purpose and existing contract

CFB1's standard core-model migration is functionally complete offline. Current
weekly BCF ratings still have to be supplied manually. This workflow replaces
source-code/notebook pasting with a versioned-by-boundary filesystem input and
an offline readiness command. **BCF acquisition is not automated.** No scraping,
browser automation, price acquisition or model calculation is in this loader.

The unchanged `bcf.py` contract comes from CELL 13, CELL 14 and OLD CELL 19 in the
frozen notebook, documented in `EPA_BCF_FEI_CONTRACT.md`. Final handoff requirements
are unchanged: retain unpriced candidates and preserve AUDIT_UNAVAILABLE when
verified openers are absent. Supplying BCF does not fabricate market data, an
opener, supplied odds, probabilities or a final decision.

## Weekly file convention

```
data/bcf/YYYY/week_##/bcf.csv
data/bcf/YYYY/week_##/bcf.metadata.json
```

YYYY is the explicit season; ## is the **target** week, zero-padded to two digits.
There is no hard-coded current season or week. `weekly_bcf_path(root, season,
week)` returns that CSV path without creating files. Explicit external CSV paths
are also accepted; their default sidecar is `<CSV stem>.metadata.json`, or supply
`--metadata`. A conventional year/week path must match the requested boundary.
The input CSV and sidecar are never modified by validation or loading.

Copy the reusable templates into the appropriate directory:

- `data/bcf/templates/bcf.csv`: headers only, no fabricated/example ratings.
- `data/bcf/templates/bcf.metadata.example.json`: deliberately unfilled metadata;
  copy/rename it to `bcf.metadata.json` and supply real values.

Use your actual season/week values when creating the directory. For example,
these commands use environment variables you explicitly set for your run:

```bash
BCF_RUN_DIR="data/bcf/${CFB_SEASON}/week_$(printf '%02d' "$CFB_TARGET_WEEK")"
mkdir -p "$BCF_RUN_DIR"
cp data/bcf/templates/bcf.csv "$BCF_RUN_DIR/bcf.csv"
cp data/bcf/templates/bcf.metadata.example.json "$BCF_RUN_DIR/bcf.metadata.json"
```

Populate the CSV from the actual weekly BCF source, then fill these sidecar
fields (the template uses null/empty placeholders intentionally):

| Field | Requirement |
| --- | --- |
| season | Integer season, exactly equal to the requested run season |
| week | Integer target week, exactly equal to the requested run week |
| data_through_week | Integer completed-data boundary, exactly equal to the requested boundary |
| source | Nonblank actual source URL or citation for the supplied ratings |
| retrieved_at | Actual retrieval timestamp in ISO 8601 with an explicit timezone, e.g. a real timestamp ending Z or +00:00 |

The existing FeatureBoundary convention requires `1 <= data_through_week < week`
and a positive season. Preseason/week-zero behavior is not introduced. The
sidecar is an operator assertion of vintage, not an independent measurement of
the source's contents. Do not relabel old ratings as current. No freshness-age
policy or timestamp-based statistical adjustment is introduced. A SHA256 of the
exact CSV bytes is included in every validation report for traceability; a prior
successful report is not a cache or permission to reuse subsequently edited data.

## Required CSV schema

Exact case-sensitive required columns:

```csv
Team,FEI,OFEI,DFEI,SFEI,OAY,DAY
```

One row per canonical team. All six rating fields must contain numeric values;
missing/blank/non-numeric/nonfinite values fail. No ratings are averaged, filled,
clipped, rounded or recalculated. Negative ratings are allowed; no new rating
range, FEI decomposition or plausibility formula is invented.

The source parser only rejected numeric conversion/null failures. This production
input boundary additionally rejects infinity as an invalid supplied value; it
changes no model formula or committed BCF parsing behavior.

Extra columns are **reported and ignored**, including any incidental metadata
columns; they do not replace the sidecar. Only the seven BCF fields reach the
existing parser. The canonical `CFBD_Team` column is generated by the shared
normalizer, never trusted from a supplied extra column. Required column order is
not mandatory, although the template uses the established order. Duplicate CSV
headers and rows with an inconsistent number of CSV fields are rejected.

Names follow the shared BCF identity behavior: trim leading/trailing whitespace
with the existing parser; apply the existing BCF_TO_CFBD mapping through
TeamIdentityResolver/normalize_bcf. Examples include Connecticut→UConn and
Appalachian State→App State. Internal whitespace, case, punctuation and mascots
are not guessed away. Market/Covers aliases are not substituted for BCF aliases.
No aliases are added automatically.

Raw duplicate teams and canonical collisions are rejected, including differently
spelled/whitespace variants resolving to the same team. Blank Team and unresolved
names fail. Diagnostics include all inspectable numeric and identity defects,
not only the first parser exception.

## Coverage and schedule scope

The legacy merge requires **all teams on the target slate**, not every FBS team
nationally. A slate-only BCF file is valid. Known canonical BCF teams not on the
slate are permitted and listed in the report. Every supplied row must still
resolve against the **full CFBD feature universe**, including non-slate rows;
unresolved extra teams remain a failure. This is the existing CELL 14 contract.

The CLI accepts saved raw CFBD `/games` JSON for the explicit regular-season
week, and the migrated `df_cfbd.csv` feature snapshot with its `team` column.
Use the feature universe from the matching completed-data boundary, not an alias
list, a truncated slate-only registry or a synthetic replacement. Generation and
validation of those snapshots remain the responsibility of the existing CFBD
acquisition workflow. This command does not fetch them or independently certify
their source/vintage; BCF readiness does not imply the full CFBD matrix is valid.

CLI scope is explicitly **FBS versus FBS**. Both homeClassification and
awayClassification (or their unambiguous snake-case variants) must be supplied
by CFBD; classification is never guessed from membership. Non-FBS/FBS games are
listed under excluded_schedule_games with OUTSIDE_FBS_VS_FBS_SCOPE. The command
makes no readiness claim for those excluded matchups. If they are needed for a
broader run, establish that run's coverage separately through the Python input
interface using its complete canonical target slate; do not interpret this CLI
report as covering them. This scope does not modify the earlier model or schedule
modules.

The selected FBS/FBS records must pass the existing normalize_cfbd_schedule
foundation, including exact season/week, team identity, game-ID/matchup uniqueness
and confirmed kickoff. Invalid schedules do not become smaller valid slates.
No target games means no production-ready coverage claim. Wrong-week records
fail even if they would otherwise be outside scope.

Optional `--target-date YYYY-MM-DD` selects the target Eastern game date after
weekly schedule validation. Without it, coverage is required for the **entire
week**. Date-excluded games are explicitly reported with OUTSIDE_TARGET_DATE.
This prevents validating only a three-game market subset while claiming full
Saturday/week coverage. A game missing from Covers is still in the official
BCF coverage denominator for the chosen scope; nothing is silently filled.

## Validation command

From the repository root, set the season, target week and completed-data week
explicitly, and point at your actual saved CFBD inputs:

```bash
PYTHONPATH=src python -m cfb1.bcf_validate \
  --file "$BCF_RUN_DIR/bcf.csv" \
  --season "$CFB_SEASON" \
  --week "$CFB_TARGET_WEEK" \
  --data-through-week "$CFB_DATA_THROUGH_WEEK" \
  --features "$CFBD_FEATURE_CSV" \
  --games "$CFBD_GAMES_JSON"
```

For a daily slate, append `--target-date "$CFB_TARGET_DATE"`. `--metadata` is
optional when using the default sidecar filename. Redirect stdout to a report
file if you want to retain it; the validator itself writes nothing.

JSON report includes:

- season, week, data_through_week, source/metadata and exact CSV SHA256;
- rows supplied, unique raw names and unique canonical teams;
- duplicate raw names, duplicate canonical names and duplicate headers;
- unresolved identities with CSV row numbers;
- malformed/blank/nonfinite rating values by field and CSV row;
- missing required columns and ignored extra columns;
- scheduled_fbs_teams_not_represented;
- bcf_teams_not_on_target_slate;
- target date, target-game count, explicit schedule scope/exclusions;
- errors and production_ready.

CSV row numbers count the header as row 1; ordinary blank lines are ignored as
in pandas. If schema/CSV/context is too malformed to inspect, coverage or unique
counts cannot be certified; production_ready is false and errors explain the
failure. Fix malformed structure before relying on detailed counts.

Exit codes: **0** BCF production-ready for the stated input boundary/scope;
**1** inspected BCF/metadata file not ready; **2** unusable run context/configuration
or schedule/feature-file read failure. No network, key lookup or scraping occurs.

Production-ready means matching metadata, nonempty valid CSV, valid context,
zero duplicate/unresolved/invalid fields, complete target coverage, and success
through the unchanged parse_bcf_csv + normalize_bcf gates. It is not a guarantee
that an operator copied the correct source values, or that the entire live model
is ready. Optional source ratings should be checked manually against the cited
snapshot before use.

## Pipeline consumption

No full live orchestration is added. The production interface is:

```python
from cfb1.bcf_weekly import load_weekly_bcf, merge_weekly_bcf

bcf = load_weekly_bcf(
    bcf_file_path,
    season=season,
    week=target_week,
    data_through_week=data_through_week,
    canonical_team_names=features.df_cfbd.team,
    target_market=target_market,
)
```

This returns the normal BCF DataFrame with canonical CFBD_Team, ready for the
existing `merge_bcf(master, bcf)`. Alternatively, the narrow convenience boundary
performs that unchanged merge:

```python
master_bcf = merge_weekly_bcf(
    master, bcf_file_path,
    season=season, week=target_week, data_through_week=data_through_week,
    canonical_team_names=features.df_cfbd.team,
)
```

Use the upstream canonical target-market/master inputs, with Home_CFBD_Name and
Away_CFBD_Name already established by the shared identity foundation. The
convenience merge validates coverage of the actual master; use the CLI or
validate_weekly_bcf with the full intended official slate first when the master
excludes missing-market games. Both interfaces re-read/revalidate files, raise
WeeklyBCFValidationError with the readiness report on failure, and perform no
model calculations or writes. Existing EPA/FEI/Module 3/routing/probability/
handoff modules consume their normal outputs unchanged.

## Tests, operations and remaining work

Offline tests cover valid slate-only files, raw/canonical duplicates, malformed
schema/numerics/CSV, finite values, whitespace/BCF aliases, unresolved identities,
known non-slate teams, absent required slate teams, metadata/path boundaries,
missing metadata, header-only templates, extras, CLI exits and complete diagnostic
fields, FBS/date scope, invalid schedules, no-network execution, revalidation
following edits and exact existing parser/merge parity.

Full regression: `PYTHONPATH=src python -m unittest discover -s tests` passes
**496 tests**, including **29 new weekly BCF tests**. Existing parser/merge parity
passes, and CLI tests prohibit network socket creation.

Weekly manual inputs remain:

1. Actual BCF Team/FEI/OFEI/DFEI/SFEI/OAY/DAY values from the proper weekly source.
2. Correct season, target week, completed-data boundary, source citation and actual
   retrieval timestamp in the sidecar.
3. Correct saved CFBD feature and weekly schedule inputs, plus intended date scope
   if running a daily slate.
4. Review and correct unresolved names/missing teams; do not invent ratings or
   add aliases without independent verification.

Current-week BCF file ingestion is now possible without notebook/source editing;
this task does not supply an actual current-week dataset. Acquisition therefore
remains manual. Later work could automate licensed/provider exports or acquisition
and preserve source snapshots, or add weekly orchestration. No scraping/browser
workflow is introduced now. Model-core migration is complete for the standard
path; experimental team totals remain outside it. Live run readiness still needs
real weekly BCF plus the other already documented operational inputs; optional
valuation requires externally supplied odds, and movement readiness requires
verified openers. No core-model formula migration is added or required by this
input workflow. Nothing is staged, committed or pushed.
